## Context

Projects need useful shape-flow evidence even when they have no Spec or schema
library. Build a deliberately small abstract interpreter over the safe source
and kondo evidence supplied by #0061.1. It reports only facts supported by
source forms and preserves partial knowledge instead of inventing types.

This ticket owns **baseline value-shape facts** only. #0061.3 owns a separate
Spec-constraint domain; a declared required/optional key never mutates or
substitutes for baseline present/maybe/absent facts.

## Shape Domain and Provenance

- [ ] Implement only these canonical baseline shapes: `:unknown`; `:nil`;
      scalar `:string`, `:integer`, `:float`, `:boolean`, `:keyword`,
      `:symbol`, `:uuid`, `:regex`; `:union` with sorted/deduplicated members;
      `:map`; and homogeneous `:vector`. A fact is
      `{:shape shape :completeness :complete|:partial :provenance [...]}`;
      partial means the represented facts survive but an unknown remainder
      exists. Do not emit runtime literal values other than map keys.
- [ ] A map is `{:kind :map :openness :open|:closed :entries [...]}`. Each
      sorted canonical-key entry has `:presence :present|:maybe|:absent|:unknown`,
      a nested fact, and zero or more read observations. `:present` means the result is
      statically known to contain the key; `:absent` means the operation proved
      it is absent even on an open map; `:maybe` means either presence is
      possible; an observed read is evidence only and never changes presence.
      Unlisted keys are absent for a closed map and unknown for an open map.
- [ ] A vector records `:element` and `:length {:min n :max n|:unknown}`.
      Literal vectors are exact-length. The baseline deliberately has no
      positional tuple form; #0061.3 represents declared tuples separately as
      Spec constraints. All other sequences are `:unknown` unless a supported
      operation proves this vector representation.
- [ ] Every shape fact and gap carries sorted provenance records with one of
      `:literal`, `:binding`, `:key-read`, `:transform`, `:call-handoff`,
      `:branch-join`, or `:opaque-boundary`, plus location and the affected
      lexical value/path. Evidence from different paths is retained rather
      than overwritten.
- [ ] Use this finite join/order for key presence: `:present` and `:absent`
      are incomparable; each is below `:maybe`; `:maybe` is below `:unknown`.
      Thus equal facts join unchanged, present+absent, present+maybe, and
      absent+maybe join to maybe, and unknown joined with anything is unknown.
      Complete is below partial, so any partial contributor makes the joined
      fact partial. Equal scalar shapes join unchanged; unequal shapes form a
      sorted union; union joins deduplicate members; maps/vectors join
      structurally as specified below; `{:kind :unknown}` is top and joined
      with any non-map/non-vector fact yields unknown/partial. A map with known
      entries can retain those entries only when both contributors are maps;
      otherwise its whole result is unknown/partial. This order is the sole
      branch and SCC widening order.

## Transfer and Control-Flow Semantics

- [ ] Interpret only `defn`/`fn`, `let`/`let*`, `do`, `if`, `if-let`, `when`,
      `cond`, map/vector literals, keyword invocation, `get`, `get-in`,
      `assoc`, `dissoc`, `merge`, `select-keys`, `update`, and one-step
      `->`/`->>` threading with a statically resolved callee. These forms are an explicit
      interpreter allowlist, not macro expansion. `defn`, binding/control
      forms, and the two threading macros are recognized syntax; every other
      macro is an opaque boundary.
- [ ] Define exact baseline transfers. Map literals produce closed maps with
      present supported scalar literal keys (non-scalar keys are opaque-entry
      gaps); vector literals produce exact vectors; function bodies and explicit
      `do` evaluate left-to-right and use the final form's fact. `(get m k)` and
      `(:k m)` return a known present key fact, nil for known absence, or
      key-shape union nil for maybe/unknown; `(get m k default)` and
      `(:k m default)` substitute the default fact for known absence and union
      it for maybe/unknown. `get-in` repeats that rule over a
      literal-key path and applies its optional default at the first absent or
      unknown segment. Map destructuring supports only `{:keys [simple-symbol
      ...] :as simple-symbol?}`; each binding uses the same lookup rule as
      `get`, mapping an unqualified symbol to its same-name keyword and a
      namespaced symbol to its same namespace/name keyword. Vector destructuring
      supports only `[simple-symbol ... :as simple-symbol?]`; each binding uses
      the vector element fact unioned with nil unless the known minimum length
      proves its position exists. Both record reads/bindings and assert neither
      map nor key presence; defaults, nesting, `:strs`, `:syms`, and rest
      destructuring are opaque.
- [ ] Apply core transfers only when kondo resolves the callee to the intended
      `clojure.core` var. For a map-compatible receiver and literal keyword
      arguments, `assoc` processes every key/value pair left-to-right;
      `dissoc` processes every key left-to-right; `merge` processes known map
      operands left-to-right and is right-biased; `select-keys` returns a
      closed map with only literal selected keys; and `update` supports one
      literal key and only updater `clojure.core/identity` with no extra args.
      `assoc`/`update` preserve closedness; `dissoc` preserves it and records
      absent keys; `merge` is closed only when every operand is closed;
      `select-keys` is closed. A right-side maybe key preserves a present left
      key as present and unions its value facts; it makes an absent left key
      maybe. Any literal-key `update` result contains that key: an unsupported
      updater makes it `:present` with a partial/unknown value and preserves
      all unaffected facts.
- [ ] Dynamic `assoc`, `dissoc`, and `update` do not preserve a misleading
      precise map: dynamic assoc/update make every known key value partial and
      open the map; dynamic dissoc downgrades every present key to maybe;
      dynamic update downgrades absent keys to maybe and all other value facts
      to partial. Any non-map-compatible receiver makes the result unknown.
      Emit the affected-path gap in every case.
- [ ] Join `if`, `if-let`, `when`, and `cond` branches structurally. `when`
      and a `cond` with no default join an implicit nil branch. Equal facts
      survive; maps join pointwise (present+absent => maybe, openness closed
      only if all branches are closed); vectors join element facts and min/max
      bounds; unlike kinds form a sorted union. `if-let` adds only a truthiness
      fact, never a type fact. Loops, recursion in local bindings, exceptions,
      `recur`, and unrecognized control forms are opaque and do not fabricate a
      return shape.

## Direct Interprocedural Scope

- [ ] Starting at requested targets, follow the direct-call closure of resolved
      local vars to a maximum depth of 12. Correlate a parser call form with a
      kondo `:direct` usage by file, enclosing definition identity, and the
      root-relative range of the call-head token (not the enclosing list). Zero
      or multiple matches are a gap, not a guessed edge.
- [ ] Map positional arguments to fixed positional parameters and return shape
      to the lexical call-site binding/expression. Support one fixed arity per
      definition plus map/vector destructuring in those parameters. Multiple
      matching definitions, variadics, unsupported parameter destructuring,
      function-valued invocation, protocol/multimethod dispatch, and dynamic
      resolution yield an explicit gap and no callee summary.
- [ ] Analyze recursive strongly connected components from a bottom
      uninitialized fact for at most eight iterations. The partial order is
      pointwise information inclusion; widening is the structural join above.
      Depth counts edges from a requested target, with its own body at depth
      zero. On non-convergence, retain the eighth iteration's facts with
      `:completeness :partial`/unknown remainder and emit one
      `:fixpoint-limit` gap per component. A missing requested target is an
      unresolved target record from #0061.1, never silently omitted.

## Acceptance Criteria

- [ ] Populate the EDN v1 `:summaries` and `:flows`/`:gaps` fields with the
      domain, identities, provenance, and semantics above; document populated
      records and canonical sorting in `languages/clojure.md`.
- [ ] Output remains byte-identical under repeated runs and target order
      permutations. Unsupported forms preserve unaffected proven facts and
      always identify the affected value/path.
- [ ] Golden fixtures cover each allowed transfer, absent vs maybe vs observed
      read, nested reads, dynamic keys, opaque macros, branch joins, direct
      argument/return handoffs, multiple arities, unresolved calls, recursion,
      depth and fixpoint limits, `.bb`, and a project with no Spec forms.

## E2E Spec

GIVEN a schema-free fixture whose entry var builds a map, reads optional keys,
uses supported transformations, crosses a direct local call, joins two
branches, and reaches an opaque higher-order call
WHEN the helper analyzes that entry var
THEN its EDN distinguishes constructed/preserved/maybe/observed facts and
argument-return handoffs, while marking only the opaque affected path unknown.

## Notes

This ticket does not treat a predicate, destructuring form, or observed key
read as a contract. #0061.3 is the only source of optional existing-Spec
