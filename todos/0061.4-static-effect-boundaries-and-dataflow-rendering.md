## Context

The dataflow skill's functional-core/imperative-shell reading is useful only
when effect labels are as conservative as its shape labels. Add a static,
evidence-backed effect pass and define exactly how the skill turns the helper's
EDN into an honest compact ASCII graph. This is the integration point for
optional Spec records from #0061.3.

## Effect Classification Contract

- [ ] Emit one effect record per analyzed function with `:kind` one of
      `:pure`, `:side-effecting`, `:mixed`, or `:unknown`, a sorted list of
      direct evidence records, and explicit gaps. A `!` suffix is never
      evidence.
- [ ] Apply a registry entry only when kondo resolves the exact fully-qualified
      callee identity and listed arity. `:pure` requires every executed form to
      be a literal/local binding/control form, a baseline-supported map
      transformation with compatible proven operands, or a resolved local
      callee classified pure. The v1 pure direct-call registry is deliberately
      closed: `clojure.core/get` (2/3), `get-in` (2/3), `contains?` (2),
      `assoc` (3+ odd), `dissoc` (2+), `merge` (0+), `select-keys` (2),
      `identity` (1), `nil?` (1), `some?` (1), `map?` (1), `vector?` (1),
      `string?` (1), `keyword?` (1), `int?` (1), `integer?` (1), and `pos?`
      (1). Opaque/custom operands, callbacks, and every other direct call are
      unknown; no friendly name-based purity inference is allowed.
- [ ] Classify only these resolved direct calls as proven
      `:side-effecting`/ambient: `clojure.core/slurp` (1+), `spit` (2+),
      `println` (0+), `print` (0+), `prn` (0+), `swap!` (2+), `reset!` (2),
      `compare-and-set!` (3), `alter` (2+), `commute` (2+), `send` (2+),
      `send-off` (2+), `deliver` (2), `require` (1+), `load` (1+), `eval` (1),
      `rand` (0/1), `rand-int` (1), `java.lang.System/currentTimeMillis` (0),
      and `java.lang.System/getenv` (0/1). `future`, `pmap`, arbitrary Java
      interop/reflection, and all dereferences are unknown in v1; do not infer
      atom/ref/agent/dynamic-var identity from the baseline shape domain.
- [ ] Any unresolved/external call not in either registry, protocol or
      multimethod dispatch, function-valued invocation, macro outside the
      #0061.2 allowlist, exception construct, unsupported form, or incompatible
      operand makes the enclosing function `:unknown` unless a known effect is
      also present. Define a non-trivial pure transformation mechanically as a
      literal map/vector construction, a supported #0061.2 map transformation,
      or a compatible pure-registry call whose result is not merely a local
      passthrough. A known effect plus at least one such transformation is
      `:mixed`; a known effect without one is `:side-effecting`. Unknown
      evidence remains a gap even when the final kind is mixed/effecting.
- [ ] Compute effects with the monotone bit lattice
      `{:effect? boolean :pure-transform? boolean :unknown? boolean}` from
      bottom all-false and bitwise-OR join; use the same depth/eight-iteration
      limits as #0061.2. Classification is deterministic: no effect + no
      unknown => pure; effect + pure-transform => mixed; effect without
      pure-transform => side-effecting; no effect + unknown => unknown. An SCC
      is pure only when every non-SCC form satisfies the pure rule. A direct
      evidence record is `{:kind :direct :callee|:form symbol :location
      location :path [definition-id]}`; propagated evidence changes only
      `:kind` to `:transitive` and appends each caller definition id. Sort by
      kind, location, callee/form, then path.

## Dataflow Skill Rendering Contract

- [ ] Update `shared/skills/dataflow/SKILL.md` to call the Clojure helper
      before manual tracing, explain the source-only boundary, and replace the
      current “Clojure not yet supported” exception. Do not call Clojure
      shape facts “types”.
- [ ] Add `languages/clojure.md` rendering guidance: edges label named
      declared Spec shapes separately from constructed/source shapes; observed
      reads never imply present keys; `s/valid?` is shown only as a true-branch
      validation boundary; opaque values/calls/effects have inline `⚠` gaps.
- [ ] Include a complete checked-in EDN fixture and an **illustrative** expected
      ASCII graph. There is no executable renderer in v1, so do not claim
      byte-for-byte renderer agreement; instead test the EDN facts and keep
      the Markdown example synchronized during review. The graph must show a
      source map, constructed map shape, one direct handoff, a branch-local
      Spec validation site, an IO boundary, and an unknown gap. The legend
      defines `[pure]`, `[IO: ...]`, `[mixed ⚠]`, and `[unknown ⚠]` without
      claiming runtime execution.
- [ ] Add two explicit hypothesis handoff examples: one where producer
      construction proves a key read by a downstream value path (a
      source-supported hypothesis), and one where the producer leaves the key
      maybe/unknown (an unresolved hypothesis). Neither example may call an
      observed read a presence proof.
- [ ] Preserve the existing skill rule: graph structure and declared shapes
      guide a concrete forward scenario trace, but cannot alone produce a
      `Confirmed` implementation verdict.

## Acceptance Criteria

- [ ] Golden fixtures cover every allowlisted pure operation category, every
      effect/ambient registry category, a pure local-call SCC, recursive SCCs,
      an unknown external call, a mixed function, and the fact that a `!`
      suffix alone changes no classification.
- [ ] EDN effect records, the full illustrative EDN-to-ASCII example, and skill
      instructions use the same evidence names and labels. `bb test` and `bb
      test:ci` execute all fixture/golden tests through the canonical entry
      point.

## E2E Spec

GIVEN an analyzed Clojure fixture with literal transformations, an existing
Spec validation branch, a filesystem write, and an unresolved external helper
WHEN an agent runs the helper and follows the dataflow skill
THEN the EDN and graph identify pure, IO, and unknown boundaries with their
static evidence, show the declared/validated/constructed shape distinctions,
and instruct the agent to validate any concrete hypothesis with a forward
scenario trace.

## Notes

This is a static classification, not proof of referential transparency or
runtime behavior. It intentionally favors `:unknown` over a friendly but
unsound `:pure` label.
