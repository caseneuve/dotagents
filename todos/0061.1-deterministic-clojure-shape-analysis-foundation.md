## Context

Shape-flow must have a reproducible and safe evidence boundary before it
interprets shapes. This ticket creates the source-only runner, not shape or
effect semantics. It defines exactly what is read, what external analyzer is
trusted, and how machine consumers receive stable EDN.

## Acceptance Criteria

- [ ] Add `shared/skills/dataflow/scripts/clj_shapeflow.clj`, executable with
      Babashka, accepting `--root PATH`, one or more fully-qualified target
      vars (`namespace/var`), and `--production-only`. Bare target names are a
      usage error.
- [ ] Discover only regular `.clj` and `.bb` files beneath the canonical root.
      Traverse neither symlinked directories/files nor any path with a hidden
      component (including hidden files), `.git`, `.clj-kondo`, or `target`.
      Sort root-relative paths by Unicode code-point order. Include
      conventional test files by default; `--production-only` excludes only a
      path component exactly `test` or `tests`, or a basename matching
      `test_*.clj`, `test_*.bb`, `*_test.clj`, or `*_test.bb`. `.cljc` and
      `.cljs` are excluded and reported once as an explicit scope limitation
      when encountered.
- [ ] Read source with a non-evaluating reader. Bind read-eval off and no
      project custom data readers; accept built-in data literals only as opaque
      literals and never invoke a project reader function. A malformed form,
      reader conditional, unknown tagged literal, discard that prevents a
      complete read, or unsupported reader form makes that file partial with a
      root-relative location and a `:source-read` gap; it never causes source
      evaluation.
- [ ] Resolve namespaces, aliases, direct var calls, definitions, arities, and
      macro markers through **exactly `clj-kondo v2026.01.19`**. Invoke it once
      per discovered file through stdin with a root-relative `--filename`,
      `--lang clj` for `.bb`, `--cache false`, and `--repro`.
- [ ] Kondo runs with a tool-owned empty `--config-dir`; it must ignore home
      and project `.clj-kondo` configuration/hooks rather than execute a
      project hook. If a project config exists, emit one
      `:project-kondo-config-ignored` gap naming its root-relative path.
      Document that custom macro resolution is therefore intentionally limited
      in v1.
- [ ] Define and document canonical EDN v1. An analyzable run writes exactly
      one EDN map plus one trailing newline to stdout and no raw kondo output.
      Its required top-level keys are `:shape-flow/version` (`1`), `:status`
      (`:ok` or `:partial`), `:root` (`"."`), `:options`, `:analyzer`,
      `:targets`, `:files`, `:definitions`, `:calls`, `:summaries`, `:flows`,
      `:spec-definitions`, `:declared-function-contracts`, `:validation-sites`,
      `:effects`, and `:gaps`. Records carry root-relative `{:file :row :col
      :end-row :end-col}` locations when applicable. All vectors are sorted by
      their documented identity; duplicate facts are emitted once; absent
      optional fields are omitted, never encoded as `nil`. Serialization uses
      a custom ordered EDN writer, never `pr-str`: every map record has the
      fixed key order and sort tuple in **Canonical EDN v1** below.
- [ ] Each target record has `:target`, `:status` (`:resolved`, `:partial`, or
      `:unresolved`), and, when resolved/partial, a definition identity. A definition
      identity is `{:var symbol :location location :arity arity}`. Calls carry
      caller identity, callee var/arity when kondo resolved it, source
      location, and `:kind` (`:direct`, `:macro`, or `:unresolved`).
      `:summaries`, `:flows`, `:spec-definitions`,
      `:declared-function-contracts`, `:validation-sites`, and `:effects` are
      reserved as empty vectors until later child tickets populate them.
- [ ] Parse each target with the non-evaluating Clojure symbol reader; require
      a symbol with nonempty namespace and name, rather than counting slashes
      (`clojure.core//` is valid). Reject all other values with exit `2`.
      Deduplicate targets by their canonical symbol and report them in Unicode
      code-point order, not command-line order.
- [ ] Define status propagation and CLI behavior. Every gap has `:severity`
      `:note` or `:partial`. A file is partial if it owns a partial gap; a
      target is partial if its definition or reachable analysis owns one; the
      run is partial if any file or target is partial. Excluded source and
      ignored project config are notes; source read errors, malformed/missing
      kondo analysis, unexplained kondo nonzero exit, no discovered source,
      unresolved/ambiguous targets, and unresolved analysis boundaries are
      partial. Exit `0` only for `:ok`; exit `1` for an analyzable `:partial`
      run after writing canonical EDN; exit `2` for invalid CLI arguments (no
      stdout); exit `3` when the pinned kondo binary/version is unavailable
      (no stdout). Human diagnostics go to stderr only.
- [ ] Add reproducible test wiring: the test image installs the pinned kondo
      version, `bb test` exercises the helper in the container, and `bb
      test:ci` invokes the same tests directly. No “if needed” environment
      work is deferred.
- [ ] Fixtures and golden tests cover byte-identical repeated runs, target-order
      permutations, path normalization/no absolute paths, `.bb` discovery,
      production filtering, ignored symlinks/hidden files, malformed source,
      ignored project kondo config, missing kondo, wrong kondo version,
      invalid roots/targets, empty discovery, duplicate definitions, malformed
      or missing kondo analysis sections, unexplained kondo failure, and a
      read-only root with a custom data-reader/load sentinel proving application
      code was not run.

## Canonical EDN v1

The ordered writer emits top-level keys in the order listed above. `:targets`
is sorted by `[str :target]` and contains
`{:target symbol :status :resolved|:partial|:unresolved :definition-id? id}`.
`:files` is sorted by `:path` and contains `{:path string :status :ok|:partial}`.
`:definitions` is sorted by `[str :var :arity location]` and contains
`{:id string :var symbol :arity int :location location}`. `:calls` is sorted
by caller id, location, callee var, and arity, and contains
`{:caller-id string :callee symbol? :arity int? :location location :kind kw}`.
Every gap is sorted by `[severity kind location subject]` and contains
`{:kind keyword :severity :note|:partial :location? location :subject? string
 :details? string :affected? value-id|path :provenance [provenance...]}`. A
shape/effect gap associated with a lexical value must provide `:affected` and
provenance; root/discovery gaps omit both. Later records retain this fixed recursive convention:
`:summaries` sort by `:definition-id` and contain `{:definition-id id
 :inputs [{:param int :fact fact}...] :output fact :completeness kw
 :provenance [...] :gaps [...]}`; inputs sort by `:param` and support every
 fixed parameter position;
`:flows` sort by source location/from/to and contain `{:from value-id :to
 value-id :fact fact :provenance [...] :gaps [...]}`; `:spec-definitions` sort
by name/location and contain `{:name keyword :constraint map? :location
 location :provenance [...] :gaps [...]}`; `:declared-function-contracts` sort
by target/location and contain `{:target symbol :args [...] :ret map?
 :location location :provenance [...] :gaps [...]}`; `:validation-sites` sort
by location and contain `{:spec keyword? :value-id value-id :relation kw
 :overlay map? :location location :provenance [...] :gaps [...]}`; and
`:effects` sort by definition id and contain `{:definition-id id :kind kw
 :evidence [...] :gaps [...]}`. A definition id is the EDN vector
`[symbol arity root-relative-file row col]`—not a string encoding—and
`value-id` is `{:definition-id id :path path}`. A path is a vector of only
`[:param n]`, `[:local symbol]`, `[:return]`, `[:map-key canonical-key]`,
`[:vector-element]`, `[:vector-index n]`, or `[:call-result location]`.
Provenance sorts by location, kind, then path.

Nested baseline shapes use only: scalar `{:kind :scalar :name kw}`; nil
`{:kind :nil}`; unknown `{:kind :unknown}`; union `{:kind :union :members
[shape...]}`; vector `{:kind :vector :element fact :length {:min n :max
n|:unknown}}`; and map `{:kind :map :openness :open|:closed :entries
[entry...]}`. Each entry is `{:key canonical-key :presence kw :fact? fact
:reads [read...]}` and each read is `{:path path :location location}`. Map
entries sort by canonical-key; union members sort by their recursively ordered
EDN representation. A canonical key is a supported literal scalar keyword,
symbol, string, integer, float, boolean, nil, or UUID, ordered by that type
rank then ordered EDN representation. A non-scalar map key is an opaque-entry
gap, never inserted in `:entries`. Spec constraints use fixed records:
`{:kind :scalar-constraint :name kw}`, `{:kind :nil-constraint}`,
`{:kind :reference-constraint :name kw}`, `{:kind :predicate-constraint
:var symbol}`, `{:kind :union-constraint :members [...]}`,
`{:kind :conjunction-constraint :structural constraint? :predicates [...]}`,
`{:kind :map-constraint :openness :open :requirements [requirement...]
:arbitrary-key-constraint? constraint :arbitrary-value-constraint? constraint}`,
`{:kind :collection-constraint :collection-kind :any|:vector :element
constraint}`, and `{:kind :tuple-constraint :items [constraint...]}`.
Requirements sort by canonical key and are `{:key canonical-key :presence
:required|:optional :constraint? constraint}`. Constraint members sort by
kind/name then recursive ordered EDN representation.

Effect evidence is `{:kind :direct|:transitive :callee? symbol :form? symbol
:location location :path [definition-id...]}`; it sorts by kind, location,
callee/form, then path. Every effect record preserves direct evidence and any
transitive propagation path.

## E2E Spec

GIVEN a read-only fixture root containing ordinary `.clj` and `.bb` files,
ignored source kinds, a project kondo config/hook, and a source-level custom
reader sentinel
WHEN the helper is run for ordered and permuted fully-qualified targets
THEN it emits byte-identical, root-relative EDN or the documented partial/fatal
result, never invokes the sentinel or project hook, and never emits raw kondo
output.
